1. ONBOARDING
=============
Steps (OnBoardingStep): WELCOME → PROFILE → PERMISSIONS → SMS_SCAN → ACCOUNT_SETUP

WELCOME     "Welcome to Cashiro" + launcher icon + SMS value prop
PROFILE     name, avatar (10 built-in), background color
PERMISSIONS READ_SMS + RECEIVE_SMS (can skip)
SMS_SCAN    WorkManager OptimizedSmsReaderWorker over inbox for chosen period
ACCOUNT_SETUP pick main account / currency (default AED)

If SMS was already granted (upgrade path), onboarding auto-completes.

Expected UI: full-screen steps, Material3 buttons, bottom nav hidden,
progress along the top, system theme.

Test: strings say Cashiro. Scan worker is the same PennyWise pipeline.
Cannot run permission dialogs without a device.


2. APP LOCK
===========
Settings → Security → App Lock (biometric). Timeout 0 / 1 / 5 / 15 / 30 min.
On resume, AppLockViewModel.refreshLockState(). If locked, AppLock screen
("Cashiro is Locked") with biometric prompt. Back cannot skip it.

Test: timeout dialog and flag wiring present. Biometric needs a device.


3. SMS INGEST (CORE)
====================
3a Live SMS
  SmsBroadcastReceiver (priority 999, BROADCAST_SMS)
  → combine multi-part bodies
  → SmsTransactionProcessor.processAndSaveTransaction(sender, body, ts)
  → BankParserFactory.getParsers(sender) → first parser that parses
  → hash dedupe, skip if user previously deleted
  → merchant mapping → RuleEngine (block / recategorize)
  → subscription match → Room insert + balance update
  → optional Firefly auto-sync worker
  → notification with Confirm / Delete / category chips

3b Inbox scan
  Settings → SMS Scan Period (3 months / all / custom date)
  OptimizedSmsReaderWorker: channel of inbox rows, same processor.

3c Bank app notifications
  BankNotificationListenerService for allowed packages (FAB, ENBD, etc.)
  Same processor. Retry via BankNotificationRetryWorker.

UAE parsers (same as PennyWise):
  FABParser, EmiratesNBDParser, LivBankParser, ADCBParser,
  MashreqBankParser, EmiratesIslamicParser.

Duplicates: transactionHash unique. Rescan does not re-insert.
Deleted hashes stay skipped.

Expected UI: toast/notification on parse; Home recent list updates;
progress dialog during scan (SmsParsingProgressDialog).

Test: TransactionDeduplicationTest, SmsScanParamsCalculatorTest,
SmsBroadcastReceiverRequestCodeTest, BankNotificationDedupHashTest PASS
in App Unit Tests. Parser-core has TestFABParser, TestLivBankParser,
EmiratesNBDParserTest.

15. FIREFLY III (OPTIONAL, ONE-WAY)
===================================
Settings → Firefly III. Off by default.

Connect: base URL + Personal Access Token (EncryptedSharedPreferences,
not in backups). Test connection GET /api/v1/about.

Mapping dropdowns only:
  GET /api/v1/accounts?type=asset
  GET /api/v1/categories
  User maps Cashiro account/category → Firefly name.

Push (syncTransaction / syncTransactionsBatch / resync all):
  external_id = pennywise-{transactionHash}
  search: GET /api/v1/search/transactions?query=external_id_is:"…"
  miss        → POST create, original_source=cashiro,
                error_if_duplicate_hash=true
  found+owned → PUT that journal only (isOwnedByCashiro: remote
                external_id equals ours)
  found+other → SKIP "Firefly-native entry — left untouched"
  never pulls Firefly rows into Cashiro
  failed rows → FireflyFailedSyncs + FireflyRetryWorker
  auto        → FireflyAutoSyncWorker on interval

Resync all walks every local row with the same rules — no second create
if the hash already exists on Firefly.

Expected UI: URL + PAT fields, test button, mapping lists, sync now,
failed-syncs screen.

Test: ownership logic reviewed in FireflyClient.kt (lines ~832–860,
1088–1092, 1275–1280). No live Firefly in CI. Compile PASS.

  Firefly external_id prefix still pennywise-{hash} (stable IDs; changing
  it would duplicate journals).
